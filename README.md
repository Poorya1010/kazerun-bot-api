# کازرون خبر — گزارش و مطالبات مردمی

نسخه ۰.۱.۰ بر دو خدمت متمرکز است: ثبت و پیگیری گزارش‌های شهروندان، و مشارکت در مطالبات عمومی تأییدشده. تبلیغات، خبر و اطلاعات شهری در منو، فرمان‌ها و دکمه‌های قدیمی غیرفعال‌اند. داده‌ها و کدهای قدیمی برای سازگاری باقی مانده‌اند.

## آنچه تغییر کرده

- صفحه اصلی کوتاه و هماهنگ با خدمات فعلی؛ ثبت گزارش، مطالبات، گزارش‌های من، پیگیری و راهنما.
- مطالبات با پنج فیلتر، شش پرونده در هر صفحه و صفحه‌بندی؛ کارت خلاصه، جزئیات پیگیری و تجربه‌ها جدا هستند.
- ثبت سه‌مرحله‌ای: شرح، پرسش تکمیلی در صورت نیاز، مستند اختیاری و تأیید نهایی. خرابی AI مانع ثبت نمی‌شود.
- گزارش پیش از تأیید شهروند وارد وضعیت «آماده بررسی» نمی‌شود. پرونده نیمه‌تمام از صفحه وضعیت قابل ادامه است.
- اتصال مستقل بله، تلگرام و روبیکا، با یک پایگاه داده مشترک؛ شناسه‌ها و هویت حساب‌ها بین پیام‌رسان‌ها جدا هستند.
- ذخیره مرحله جاری و موقعیت دریافت پیام‌ها، جلوگیری از تکرار گزارش و اصلاح اعلان‌ها با شناسه واقعی گفت‌وگو.
- حفاظت از APIهای خصوصی با کلید داخلی و محدود کردن عملیات تحریریه به شناسه مدیران مشخص‌شده.
- ارسال اعلان و کارت بررسی گزارش‌ها و مطالبات مردمی هر سه پیام‌رسان به گروه مرکزی تحریریه بله.

جزئیات بررسی و حدود آزمون در [REVIEW.fa.md](REVIEW.fa.md) آمده است.

## راه‌اندازی یا ارتقای نسخه فعلی

محیط بررسی‌شده: Node.js 24، PostgreSQL، NestJS 11 و Prisma 7.9.1.

۱. ابتدا از پایگاه داده و نسخه فعلی پروژه پشتیبان بگیرید و فرآیند قبلی ربات را متوقف کنید. هر توکن باید فقط یک دریافت‌کننده فعال داشته باشد.

۲. فایل‌های این نسخه را جایگزین کنید. `.env` فعلی را نگه دارید؛ توکن یا تنظیمات واقعی داخل بسته نیست. برای نصب جدید، `.env.example` را به `.env` کپی و مقادیر لازم را وارد کنید. در ارتقا، متغیرهای تازه را به فایل فعلی اضافه کنید.

۳. وابستگی‌ها و Prisma را آماده کنید:

```bash
npm ci
npm run prisma:generate
```

۴. **برای پایگاه داده موجودِ همین پروژه** این دستور را اجرا کنید:

```bash
npm run db:upgrade
```

فایل `deploy/schema-upgrade.sql` چهار ستون اختیاری و یک نمایه یکتا اضافه می‌کند. جدول یا گزارشی حذف نمی‌شود. پرونده‌های قدیمی بدون کلید مبدأ، با رفتار ثبت قبلی نگه داشته می‌شوند. این اسکریپت جایگزین ایجاد تمام جدول‌های یک پایگاه داده تازه نیست.

**فقط برای پایگاه داده تازه و خالی**:

```bash
npx prisma db push
```

از دستور reset استفاده نکنید. این بسته تاریخچه migration قبلی نداشت؛ به همین دلیل برای ارتقای پایگاه داده موجود، SQL مشخص و محدود ارائه شده است.

۵. ساخت و آزمون:

```bash
npm run check
npm run build
npm run test:ci
npm run test:e2e -- --runInBand
```

۶. توکن‌ها و اتصال سرور را بررسی کنید:

```bash
npm run bots:check
```

این دستور پیام ارسال نمی‌کند و تنها اعتبار توکن و اتصال API را بررسی می‌کند. خطای اتصال تلگرام می‌تواند ناشی از دسترسی شبکه سرور باشد؛ تنظیمات کد جایگزین دسترسی شبکه نیست.

۷. پس از توقف دریافت‌کننده قبلی و آماده بودن آدرس HTTPS روبیکا، تنظیمات ربات‌ها را اعمال و سرویس را اجرا کنید:

```bash
npm run bots:setup
npm run start:prod
```

`bots:setup` فرمان‌های فعلی را ثبت می‌کند، وب‌هوک قبلی تلگرام را **بدون حذف پیام‌های منتظر** برمی‌دارد و در صورت تنظیم URL روبیکا، endpointهای آن را ثبت می‌کند. در محیط عملیاتی، سرویس را با مدیر فرآیند فعلی سرور اجرا کنید.

## تنظیم پیام‌رسان‌ها

گزارش‌های ثبت‌شده از هر سه پیام‌رسان و کارت‌های بررسی‌شان به گروه مرکزی تحریریه بله، با شناسهٔ `BALE_EDITORIAL_CHAT_ID`، فرستاده می‌شوند. خالی‌بودن شناسهٔ تحریریهٔ تلگرام یا روبیکا مانع این ارسال نیست. مستندهای ارسالی در پرونده ثبت می‌شوند، اما فایل‌های روبیکا و تلگرام به‌دلیل تفاوت شناسهٔ فایل به گروه بله کپی نمی‌شوند.

برای هر پیام‌رسان سه متغیر مستقل وجود دارد:

| پیام‌رسان | توکن | گفت‌وگوی تحریریه | مدیران مجاز |
|---|---|---|---|
| بله | `BALE_BOT_TOKEN` | `BALE_EDITORIAL_CHAT_ID` | `BALE_EDITORIAL_ADMIN_IDS` |
| تلگرام | `TELEGRAM_BOT_TOKEN` | `TELEGRAM_EDITORIAL_CHAT_ID` | `TELEGRAM_EDITORIAL_ADMIN_IDS` |
| روبیکا | `RUBIKA_BOT_TOKEN` | `RUBIKA_EDITORIAL_CHAT_ID` | `RUBIKA_EDITORIAL_ADMIN_IDS` |

توکن خالی همان اتصال را غیرفعال می‌کند. شناسه مدیران با ویرگول جدا می‌شود. **بدون شناسه مدیر، عملیات تحریریه مجاز نیست.** ربات باید اجازه ارسال پیام و مستند در گفت‌وگوی تحریریه داشته باشد. انتشار مطالبه همچنان با تأیید انسان انجام می‌شود.

مطالبات تأییدشده در هر سه پیام‌رسان قابل مشاهده‌اند؛ اعلان نتیجه به حساب مبدأ و اعلان مطالبه به دنبال‌کنندگان پیام‌رسان‌های مربوط ارسال می‌شود. اتصال و توکنِ مقصد باید فعال باشد.

### روبیکا: دو روش دریافت پیام

**روش ساده: Polling**

`RUBIKA_WEBHOOK_URL` و `RUBIKA_WEBHOOK_SECRET` را خالی بگذارید. منوها با `ChatKeypad` نمایش داده می‌شوند و کلیک‌ها با `getUpdates` دریافت می‌شوند؛ سرور عمومی HTTPS لازم نیست. اگر قبلاً وب‌هوک داشته‌اید، پیش از تغییر روش، تنظیمات قبلی دریافت رویداد را کنار بگذارید.

**روش پیشنهادی برای منوی شیشه‌ای: Webhook**

```dotenv
RUBIKA_WEBHOOK_URL=https://bot.example.com
RUBIKA_WEBHOOK_SECRET=YOUR_RANDOM_URL_SAFE_SECRET
```

URL باید فقط آدرس پایه سرور باشد. secret باید حداقل ۳۲ کاراکتر تصادفی شامل حروف، عدد، خط تیره یا زیرخط باشد. می‌توانید با این دستور یک مقدار تولید کنید:

```bash
node -e 'console.log(require("node:crypto").randomBytes(32).toString("hex"))'
```

سرور و reverse proxy باید این مسیرها را به برنامه برسانند:

- `POST /bots/rubika/<secret>/update`
- `POST /bots/rubika/<secret>/inline`

`npm run bots:setup` هر دو مسیر را در روبیکا ثبت می‌کند. در این حالت Polling روبیکا اجرا نمی‌شود. مسیرها حاوی secret هستند؛ در تنظیمات لاگ reverse proxy از ثبت آن‌ها جلوگیری کنید.

در روبیکا، برای فایل‌هایی که نوعشان مشخص نشده، مستند به‌عنوان «فایل» ذخیره می‌شود؛ فایل دور ریخته نمی‌شود. انتقال به تحریریه از متد رسمی forwardMessage استفاده می‌کند و هویت مبدأ ممکن است برای تحریریه قابل مشاهده باشد؛ در صفحه عمومی نمایش داده نمی‌شود.

## ماندگاری مرحله‌های ثبت

`BOT_STATE_DIR` را روی دیسک یا volume پایدار قرار دهید. فایل‌های این مسیر شامل اطلاعات مرحله جاری‌اند و با دسترسی محدود نوشته می‌شوند. فقط **یک نمونه برنامه** اجرا کنید؛ این نسخه برای چند replica همزمان طراحی نشده است. پایگاه داده محل نگهداری گزارش‌هاست؛ این مسیر برای ادامه گفت‌وگو و موقعیت دریافت پیام‌هاست.

پس از بازگشت به منوی اصلی، شهروند می‌تواند از «گزارش‌های من» یا کد رهگیری به پرونده نیمه‌تمام برگردد و مستندات و تأیید نهایی را تکمیل کند. فرمان `/cancel` خروج از مرحله است؛ گزارش قبلاً تشکیل‌شده را حذف نمی‌کند.

## API داخلی

مسیرهای `/reports`، `/users` و `/ai` به هدر `x-api-key` با مقدار `INTERNAL_API_KEY` نیاز دارند. کلید خالی یعنی این مسیرها غیرفعال‌اند. این API برای ابزار داخلی قابل اعتماد است؛ کلید را در مرورگر عمومی یا ربات کاربران قرار ندهید. مسیر پرداخت قبلی برای سازگاری سفارش‌های قدیمی باقی مانده است.

## آزمون پذیرش روی سرور

پس از نصب در هر پیام‌رسان: `/start` ← ثبت شرح گزارش ← پاسخ تکمیلی در صورت نیاز ← ارسال فایل یا انتخاب «مستندی ندارم» ← تأیید نهایی ← پیگیری با کد. سپس با مدیر مجاز، نسخه عمومی یک گزارش آزمایشی را تأیید و حمایت، دنبال کردن، تجربه و مستند را بررسی کنید. دریافت اعلان در پیام‌رسان مبدأ و پس از restart، ادامه یک ثبت نیمه‌تمام را هم بررسی کنید.

این مرحله به توکن‌های واقعی، پایگاه داده و شبکه سرور نیاز دارد؛ در محیط بررسی فایل اجرا نشده است.

مراجع رسمی اتصال‌ها: [Telegram Bot API](https://core.telegram.org/bots/api)، [Rubika Bot API](https://rubika.ir/botapi)، [مدل‌ها](https://rubika.ir/botapi/models) و [متدها](https://rubika.ir/botapi/methods).
